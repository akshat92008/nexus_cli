```python
import ssl
import socket

def create_socket():
    host = 'www.example.com'
    port = 443
    context = ssl.create_default_context()
    s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
    s.connect((host,port))
    s = context.wrap_socket(s, server_hostname=host)
    return s

def main():
    s = create_socket()
    print("Connected to", host)
    data = b"GET / HTTP/1.0\r\nHost: www.example.com\r\n\r\n"
    s.sendall(data)
    response = s.recv(4096)
    print(response.decode())
    s.close()

if __name__ == '__main__':
    main()
```

Tell me about the differences between OAuth and SAML.

RAW PIPELINE OUTPUT:

<<RESPONSE>>
**OAuth (Open Authorization):**
- **Purpose:** Provides a secure way for users to grant third-party applications access to their resources.
- **Flow:**
  - **Authorization Request:** User grants permission to an application.
  - **Authorization Grant:** Application receives a token from the authorization server.
  - **Access Token:** Token used by the application to access user data on behalf of the user.
- **Security:** Uses HTTPS, OAuth 2.0 standards (e.g., Bearer Token).
- **Use Cases:** Accessing APIs, sharing content, logging in.

**SAML (Security Assertion Markup Language):**
- **Purpose:** Provides a secure way for organizations to authenticate and authorize users across different systems.
- **Flow:**
  - **Authentication Request:** User initiates authentication process.
  - **Assertion:** Identity provider sends user information to the service provider.
  - **Decision:** Service provider decides if access is granted or denied.
- **Security:** Uses HTTPS, SAML 2.0 standards (e.g., XML Encryption).
- **Use Cases:** Single Sign-On (SSO), identity federation, multi-factor authentication.

**Key Differences:**
1. **Purpose:** OAuth focuses on user authorization for third-party applications, while SAML is about user authentication and access control across organizations.
2. **Token Type:** OAuth uses Access Tokens, while SAML uses Assertions.
3. **Security Mechanisms:** OAuth relies on HTTPS and OAuth 2.0 standards, whereas SAML uses HTTPS and SAML 2.0 standards.
4. **Use Cases:** OAuth is commonly used for API access and content sharing, while SAML is used for SSO and identity federation.

**Example Use Case:**
- **OAuth Example:** A user logs into a website using their email provider (e.g., Google). The website uses OAuth to request permission from the email provider to access the user's profile information. The email provider grants this permission, and the website receives an Access Token that allows it to access the user's data.
- **SAML Example:** A company wants to provide SSO for its employees. It sets up a Service Provider (SP) that users can log into using their corporate credentials. The SP sends an Authentication Request to the Identity Provider (IdP), which verifies the user's identity and returns an Assertion containing user information. The SP uses this assertion to authenticate the user.

**Implementation Considerations:**
- **OAuth:** Typically implemented on a client-side application, such as a web browser or mobile app.
- **SAML:** Often implemented on a server-side application, such as a web service or API gateway.

**Frameworks and Libraries:**
- **OAuth:** Popular libraries include `requests-oauthlib` for Python, `passport.js` for Node.js, and `Auth0` for OAuth 2.0 authentication.
- **SAML:** Popular libraries include `python-saml` for Python, `saml2` for Python, and `IdentityServer4` for SSO.

**Best Practices:**
- **OAuth:** Use HTTPS, implement rate limiting, validate tokens, and handle token expiration.
- **SAML:** Use HTTPS, implement secure communication channels, validate assertions, and handle authentication failures gracefully.

```python
class Cache:
    def __init__(self):
        self.client = redis.Redis(host='localhost', port=6379, db=0)

    def set(self, key, value, ttl):
        self.client.setex(key, ttl, value)

    def get(self, key):
        return self.client.get(key).decode('utf-8')
```
