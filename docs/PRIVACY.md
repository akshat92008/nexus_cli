# Privacy & Data Governance Policy — Nexus CLI

Nexus CLI is designed with a **privacy-first, fail-closed architecture**. We believe developers must retain full control over their code, credentials, and telemetry.

---

## 1. Zero Remote Telemetry by Default

- Nexus CLI **does not transmit telemetry, tracking events, or usage metrics** to remote servers unless explicitly opted in by the user.
- Local audit logs are written exclusively to local disk (`.nexus/` or system cache directory).

---

## 2. Local-Only & Private Model Support

- Nexus CLI supports local LLM runtimes (e.g. Ollama, llama.cpp, vLLM) via `LOCAL_ONLY` network policy.
- Under `LOCAL_ONLY` policy, all outbound external HTTP network connections are strictly blocked by `NetworkGuard`.

---

## 3. Secret Redaction & Protection

- API keys, access tokens, credentials, and sensitive private file paths are redacted (`[REDACTED]`) before terminal rendering, log persistence, or proof artifact export.
- `FilesystemSecurity` prevents reading or exposing system credentials (e.g. `~/.ssh`, `~/.aws/credentials`, `/etc/passwd`).

---

## 4. Diagnostics & Bug Reporting

- Crash reports and diagnostic logs generated by `nexus doctor` are formatted locally.
- No source code or prompt contents are uploaded automatically.
